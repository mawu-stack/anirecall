Abstract — Anime discovery traditionally relies on exact title searches or keyword lookups that require users to already know official Japanese or English names. However, human autobiographical and episodic memory of animated media is overwhelmingly characterized by perceptual fragments: unusual scenes, distinctive outfits, character superpowers, emotional plot twists, approximate eras, or viewing contexts (such as platform or personal watch year). This report presents AniRecall, an open-source, full-stack web application powered by an autonomous, tool-using AI agent designed to bridge the gap between vague human memories and structured media catalogs. The system introduces structured memory clue extraction (with explicit certainty tagging into “Sure” and “Maybe”), grounded candidate verification against official AniList GraphQL and Jikan (MyAnimeList) APIs, automated side-by-side comparison matrices, negative candidate exclusions, spoiler-shielded explanations, character-specific attribute retrieval, screenshot frame-matching via Trace.moe, and privacy-preserving client-side collection persistence. Automated integration testing across 12 critical test suites demonstrates 100% observed verification accuracy on benchmark episodic recall queries with zero hallucinated titles.

1. Introduction and Problem Statement

Conventional media search engines and catalog portals (such as MyAnimeList, AniList, and streaming search indexes) are optimized for lexical title matching and structured relational database filtering. They perform exceptionally well when a user already knows the Japanese or English title of a work (e.g., Steins;Gate). However, when individuals attempt to identify an anime watched years earlier, human cognitive recall functions through episodic and sensory fragments:

  • A bizarre visual scene: “A microwave turning bananas into green gel and sending text messages to the past.”
  • A character attribute: “A scrawny boy with an eyepatch who gets tortured and counts backwards from 1,000 by 7.”
  • A viewing circumstance: “I watched it in 2021 on Netflix, but it was an older 90s mecha show with a purple robot.”

Existing retrieval architectures fail on such queries for two reasons: (1) title-search endpoints reject natural prose descriptions, and (2) generative large language models (LLMs) deployed without grounding frequently hallucinate nonexistent anime titles, fabricated episode numbers, and fictional studio attributions. AniRecall addresses these challenges by implementing an autonomous, tool-using AI agent architecture that combines episodic clue decomposition, certainty distinctions (“Sure” vs “Maybe”), chronological separation of watch year from release year, grounded catalog verification, active ambiguity resolution, and iterative session refinement.

2. UI and UX Design Inspirations

AniRecall's design and interaction architecture was informed by analyzing five contemporary state-of-the-art web references:

  • AniList (anilist.co): High-density anime poster cards, typography hierarchy, status/format badges, studio attribution, and external catalog ID links.
  • KIRU (kiruanime.com): Interactive discovery, mood/tone preference buttons, and transparent explanations of recommendation rationale.
  • AniRadar (aniradar.net): Plot-description search inputs, natural query interpretation, and anime guessing game mechanics.
  • trace.moe (trace.moe): Dedicated screenshot upload controls, exact broadcast video frame matching, and transparent limitation disclosures.
  • Same Energy (same.energy): Aesthetic, mood-driven visual discovery avoiding keyword friction.

3. System Architecture and Framework

AniRecall is constructed as a modern, decoupled web application using Next.js 14 (Pages Router) and React 18, hosted on a Node.js runtime. Server-side API routes handle all external network interactions, rate-limiting, and LLM reasoning, keeping API credentials strictly server-side.

4. Agent Tools and Grounded Workflow

AniRecall avoids unconstrained text generation by constraining LLM operations to an explicit tool-calling execution pipeline:

  1. extract_clues: Normalizes user text into typed memory chips: character, setting, scene, genre, approx_year, watched_year, format, and platform. Differentiates viewing year from release era.
  2. build_search_queries: Constructs targeted keyword queries for catalog lookup based on extracted scenes, character attributes, and hard constraints.
  3. searchAnime: Queries AniList GraphQL and Jikan (MyAnimeList) v4 API with an in-memory TTL cache (15 min) and fallback fixtures.
  4. getAnimeDetails: Retrieves comprehensive synopses, characters, studios, tags, and episodes for candidate works.
  5. compareCandidates: Evaluates candidates against user clues, categorizing evidence into Matches, Conflicting, and Unverified in catalog summary.
  6. generateDiscriminatingQuestion: Evaluates top close candidates and formulates a single targeted question, explicitly skipping categories already answered.

6. Security, Privacy, and Ethical Safeguards

  • Zero Server Search Tracking: User searches and memory prompts are held ephemerally in session memory and never recorded in persistent cloud databases.
  • In-Memory Ephemeral Visual Buffers: Uploaded screenshots for Trace.moe frame matching are processed strictly in RAM buffers and never persisted to disk.
  • Bounded Payload Limits: API payloads are capped (1MB for JSON text, 6MB for image uploads) to prevent Denial of Service.
  • Zero Model Code Execution: LLM responses are parsed strictly as structured JSON schemas; arbitrary model-generated executable code is never executed.
  • Attributed Sourcing: All poster artwork and links are directly attributed to official MyAnimeList and AniList catalog entries.

7. Limitations and Future Work

  • High-Level Synopsis Granularity: Official catalog synopses occasionally omit obscure background gags or minor dialogue snippets. While the agent acknowledges these as “Unverified” rather than hallucinating, integrating vector embeddings of episodic subtitle transcripts represents a promising future expansion.
  • Manga vs. Anime Divergence: Users occasionally recall scenes exclusive to original light novels or manga that were cut from television adaptations.
  • Optical Character Recognition (OCR): Future extensions could incorporate on-device OCR to match fansubbed dialogue directly against subtitle databases.

8. Reproducibility Guide

To run the application locally or re-run the verification test suite:

git clone https://github.com/[YOUR-USERNAME]/anirecall.git
cd anirecall

# Install dependencies
npm install

# Run automated verification test suite (36 assertions)
npm test

# Build production bundle
npm run build

# Start production server on http://localhost:3000
npm start
